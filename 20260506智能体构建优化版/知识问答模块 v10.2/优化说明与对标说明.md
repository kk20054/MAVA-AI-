# 知识问答模块 v10 优化说明与对标说明

## 一、现有问题判断

当前知识问答链路的方向是正确的：先通过脚本控制检索和上下文，再让模型基于证据表达。但原 `06` 阈值兜底存在一个关键风险：把检索系统返回的 `relevance` 当作单一裁判。

在 HIBOR 这类问题上，`relevance = 0` 不一定代表内容无关。它可能只是 WebSearch 的排序分数未校准、来源格式不匹配，或搜索结果结构里分数缺失。直接按阈值删除，会误删包含“日期 + HIBOR + 利率数值”的真正有用内容。

## 二、行业优秀做法借鉴

1. OpenAI File Search 的公开文档强调查询改写、关键词与语义检索并用、结果重排，并且默认不通过高阈值提前删除结果。
2. Azure AI Search 的混合检索使用 RRF 融合不同排序结果，说明不同检索器分数不可简单横向比较。
3. Anthropic Contextual Retrieval 强调 BM25 精确匹配对缩写、专有名词、代码和金融符号非常重要，不能只依赖语义相似度。
4. Amazon Bedrock Knowledge Bases 提供混合搜索、元数据过滤、重排和最大召回数控制，说明“召回”和“上下文压缩”应分层处理。

## 三、v10 落地策略

1. 意图层：
   - 增加 `query_type`，区分 INTERNAL_POLICY、FINANCE_DEFINITION、MARKET_RATE、MACRO_NEWS、ICBC_PUBLIC、GENERAL_KNOWLEDGE。
   - 对 MARKET_RATE 自动生成 `protected_terms` 和 `freshness_required`。

2. 检索层：
   - BKS 与 Web 分开筛选，避免两个来源的 relevance 分数混用。
   - 结果保留依据从单一分数变为多信号：原始 relevance、实体命中、关键词覆盖、日期、数值、期限、来源、跑题惩罚。

3. 上下文层：
   - 用 06-3 做去重和预算控制。
   - 对市场问题优先保联网结果；对行内制度优先保知识库结果。
   - 内容按命中片段截取，不再简单整条删除。

4. 生成层：
   - 提示词要求引用来源编号。
   - 明确冲突处理、低置信提示、时效性提示和免责声明。

## 四、建议继续优化方向

1. 若平台允许，为 BKS 文档增加元数据：文档日期、制度类型、来源部门、是否现行有效。
2. 为市场数据维护权威来源白名单，例如 HKAB、HKMA、交易所、央行、官方公告。
3. 对 HIBOR、SOFR、LPR 等建立专门解析器，优先抽取期限、日期、数值并生成结构化表格。
4. 建立线上评测集：每类问题至少 20 条，记录召回来源、是否命中、回答是否引用正确来源。
5. 将“无结果”和“结果过旧”区分处理，避免用户误以为系统完全无资料。
