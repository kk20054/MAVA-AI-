# 生成报告模块 v8 接入说明

## 一、设计依据

本版参考了“优化0503问数模块”会话中的落地结论：在现有模型能力和接口开发节奏下，优先采用“脚本强约束 + 模型润色”的路线。问数模块 v9 已经把经营概况、异动、贡献、风险、下钻等意图结构化，报告模块 v8 沿用同一思路，把全量报告接口数据先压缩成可控的经营诊断素材，再交由模型形成报告。

对标金蝶、用友等专业用数助手，本版优先落地当前接口可支持的能力：自动取数、模板化报告、智能归因素材、异常关注、下钻建议和格式化输出。模型只负责表达，不负责事实和计算。

## 二、推荐工作流

1. 意图守卫
   - 文件：`生成报告模块 — 意图守卫提示词 v8.txt`
   - 文件：`生成报告模块 — 路由脚本 v8.py`
   - 原则：报告、分析、总结、经营数据相关请求默认放行。

2. 参数抽取
   - 文件：`生成报告模块—参数抽取提示词 v8.txt`
   - 文件：`生成报告模块—接口参数组装脚本 v8.py`
   - 接口固定：`requestType=1`
   - 必要参数：`batch_date`、`ee`

3. 接口取数
   - 使用参数组装脚本输出的 `api_params` 调用报告接口。

4. 数据预处理
   - 文件：`生成报告模块—数据预处理 v8.py`
   - 输入：接口返回全量 `data_dict`
   - 输出：`narrative_draft`、`overview_context`、`management_diagnosis`、`structural_insights`、`signals_summary`、`suggestion_candidates`、`al_context`、`rev_context`

5. 报告生成
   - 文件：`生成报告模块—报告分析师 v8.txt`
   - 输入：预处理脚本输出的各段素材。
   - 输出：固定 Python 字典，包含“一、主要经营情况”和“二、下一步建议”。

6. 内容规范
   - 文件：`生成报告模块—process_AI_content v8.py`
   - 输出：`financial_highlights`、`key_facts`、`report_sections_json`
   - `financial_highlights` 和 `key_facts` 已做 HTML 转义并用 `<br>` 连接，便于嵌入页面。

## 三、v8 主要变化

1. 新增 `management_diagnosis`
   - 将收益、规模、结构、风险信号压缩成“关注等级｜维度｜事实｜影响”的素材。
   - 让报告更像经营管理分析，而不是逐项复述表格。

2. 优化建议候选
   - 从泛泛的“加大营销力度”改为更可执行的动作，如结算沉淀、代发代扣、到期分布、授信转化、重点客户清单等。

3. 强化银行口径
   - 损益类使用累计同比、当月同比、当月环比。
   - 资负类使用时点余额、较上年末、当月环比。
   - 禁止模型自行计算或混用口径。

4. HTML 嵌入更稳
   - 末端脚本解析 JSON / Python dict / 代码块三类常见模型输出。
   - 对输出文本做 HTML 转义，减少页面嵌入风险。

## 五、后续建议

短期可直接替换报告模块链路试跑。中期建议接口补充客户、产品、部门三类 Top N 贡献和拖累明细；长期建议在映射表中加入 `is_leaf`、`has_children`、`path`、`max_child_level`，与问数模块 v9.2 的叶子节点保护形成统一指标语义层。
