# 0503 问数模块优化建议与对标说明

## 一、现有方案判断

0503 版本的主思路是正确的：先把用户问题参数化，再通过指标接口取数，最后由脚本预计算并约束模型输出。考虑到当前模型能力和接口开发资源有限，“脚本强约束 + 模型润色”的路线比完全依赖大模型更稳。

当前主要短板不在单点代码，而在三层能力还没有完全分开：

1. 意图层：只判断放行/重定向，尚未稳定识别“概况、异动、贡献、风险、下钻、趋势”等分析场景。
2. 指标层：指标口径散落在脚本规则中，缺少统一的指标语义注册表。
3. 表达层：回答更偏“数据说明”，还可以进一步接近日常经营分析会使用的“结论、驱动、风险、动作”结构。

## 二、对标方向

参考金蝶、用友等用数/智能财务助手的公开产品表达，前沿路径通常不是让模型直接算数，而是把 AI 嵌入数据底座、指标口径、业务流程和报告模板中，强调自动取数、智能分析、异常预警、下钻追问、报告生成和流程闭环。

对 MAVA 来说，可落地版本建议采用：

用户自然语言 → 业务语义识别 → 指标参数补齐 → 接口取数 → 脚本预计算 → 诊断素材包 → 模型生成经营分析。

其中模型主要负责表达，不负责事实和计算。

   - 经营概况类问题自动补齐三大类指标和 L1/L2。
   - 需要明细/贡献/归因时自动补 L3，便于接口返回可下钻子项。

2. `data_slicing v9.0.py`
   - 增加经营诊断素材：异动识别、贡献结构、风险关注、下钻方向。

   - 明确客户维、部门维、图表等未完全对接问题先放行，由下游兜底提示处理。

## 四、下一步接口开发优先级

优先级 1：目标完成率和计划值
经营分析要真正有“管理味”，不能只和历史比，还要能和预算、目标、分解计划比。

优先级 2：客户/产品/部门三类下钻维度
客户经理最常问的后续问题通常是“谁贡献、哪个产品拖累、哪个团队异常”。建议先做 Top N 贡献和 Top N 拖累。

优先级 3：连续异动和预警阈值
例如连续两个月下降、单月降幅超过 10%、核心指标占比异常变化等，由脚本直接打标签。

优先级 4：标准报告包
把月度经营分析固定成：经营总览、资负表现、收益表现、结构贡献、异常预警、下钻建议、数据明细。

## 五、建议保留的原则

1. 数字和比较口径必须由脚本确定。
2. 模型只做语言组织和轻量归纳。
3. 表格作为事实底座必须原样附上。
4. 任何未覆盖指标要明确兜底，不要让模型猜。
5. 推荐追问要引导用户进入下一层数据，而不是泛泛提问。
